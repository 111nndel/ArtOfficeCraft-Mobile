# Document processing foundation — 0.16.0

The approved mobile interface, English/Russian UI, gestures and tool navigation
remain unchanged. This release changes document ownership, processing and history.

## Architecture

- Each native editor backend lazily owns one persistent Dart isolate and one set
  of FFI bindings. Requests are processed serially. Application data errors return
  to the caller without stopping the worker; unexpected termination settles
  pending requests as failures. Edits are never automatically replayed.
- Applied edits return a validated `DocumentSnapshot`: immutable file bytes plus
  the inspected view. Word, Grid, Deck and PDF consume that pair before publishing
  a replacement. PDF additionally opens the new Android render session first.
  A failed edit/inspection leaves the old document and pending input available.
- Immutable snapshots use identity tokens to reuse one retained worker input.
  Byte transfers use TransferableTypedData. External mutable buffers are copied
  on each request; they cannot masquerade as an unchanged cached file. Requests
  are frozen/validated before startup or token changes. Invalid/cyclic data is
  rejected before entering native code.
- PPTX pictures use that same document worker instead of one isolate per image.
  Slide authorization, media limits and format checks remain in the pinned native
  adapter. The existing bounded picture cache is unchanged.
- Owned backends close when their editor is disposed; injected backends belong to
  their caller. Shutdown first drains accepted operations and replies, then
  terminates the worker. It does not kill an isolate during an FFI call that owns
  borrowed/native buffers.
- Word moves undo/redo only after a target has been inspected and installed.
  Both history directions share one 24 MiB / 10-step budget; oversized states
  are not retained. History snapshots are immutable, including caller-supplied
  buffers. That budget covers retained history, not total application memory.

## Remaining foundation work

This is a persistent Dart worker and immutable-snapshot boundary, **not a persistent
parsed Rust document model**. Rust still parses/serializes complete Office files
for edits, and inspection can reparse the output. Large-file latency, native-model
session handles and cancellation need further work; no speedup percentage or
whole-app memory bound is claimed. A stuck native call cannot be safely canceled
by forcibly killing its isolate.

The 55 x 12 sheet preview / 1600 inspected-cell limit, 12-entry picture cache,
bounded PDF raster resolution, incomplete Office layout and session-local undo
remain. Windowed sheet data and faithful rendering are subsequent work. No
physical Vivo or runtime 16-KiB-page test was performed. Recovery still restores
only the last durably written checkpoint.
